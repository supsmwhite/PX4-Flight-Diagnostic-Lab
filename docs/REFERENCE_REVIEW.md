## 2. 通信与解析：源码事实

### 2.1 CRC 验证的重同步（S1）

- 使用 `pymavlink.dialects.v20.common`，对象保存跨输入块的 `bytearray` 和独立 decoder，能够处理 UART-over-UDP 将一个帧拆到多个 datagram 的情况。
- 识别 MAVLink 2 的 `0xFD`（10 字节头）和 MAVLink 1 的 `0xFE`（6 字节头）。长度为头、payload、两字节 CRC，加上签名标志启用时的 13 字节尾部；遇到不支持的 incompatibility flags 跳过候选。
- 仅已知 message ID 且 decoder 校验通过的候选可建立可信帧边界。未知 ID 无 CRC_EXTRA 定义，不按其声称长度跳过，而是逐字节继续寻找；CRC 失败同样逐字节继续寻找。
- 遇到不完整候选仍继续向后搜索完整好帧，避免一个损坏长度长期阻塞后续帧。最后保留可能的不完整尾部，只有实际消耗掉的候选计入错误计数，避免分块重复输入使计数膨胀。
- 暴露 `crc_errors`、`unknown_candidates`、`last_unknown_id`、`discarded_bytes` 与待解析 buffer。**CRC/已知消息边界不是发送者身份认证，也不是 MAVLink 签名认证。** 尾部长度识别不等于密码学验证。

### 2.2 被动 UDP 诊断与重放（S2）

- `capture` 创建 IPv4 UDP socket，排他绑定 `0.0.0.0:port`，只执行接收；按来源 IP 过滤，不发送握手、心跳或查询。端口冲突则提示先退出地面站/QGC，而不是通过共享绑定抢包。
- 时间用 monotonic 相对秒，原始 datagram 以 `{t,address,data}` JSONL 保存，`data` 为 Base64，文件以 `x` 模式创建避免覆盖。默认 20 秒，可配置范围 `(0,300]`。
- `analyse` 按完整来源 `(IP, source_port)` 分配独立解析器，统计 datagram 数、字节、来源、长度分布、消息类型和解析错误。
- 只将 component 1 且 autopilot 12（PX4）的 HEARTBEAT 纳入心跳明细，按 `(source,sysid)` 算相邻心跳最大时间间隔；记录 seq，但没有基于 seq 算精确丢包率。
- `--replay` 从已有 JSONL 分析，**该分支不打开网络 socket**；输出 summary JSON。代码明确提示校验失败/丢弃字节不是精确丢包率，未知候选也可能是错位噪声。

### 2.3 机队网关不等于被动诊断器（S4）

- 启用飞机按配置来源 IP 路由；监听公共端口及各启用飞机 `udp_port`，对端口去重。每机 ingress/egress 各一个解析器，来源端口改变则重置 ingress，避免两个源端口的半帧串接。
- 先检查当前解出的整组消息，再转发：任何消息 SYSID 与配置不符即隔离；component 1 的心跳还须为 PX4，成功后置 verified。身份冲突为粘滞错误，需要检查来源并重启。CRC 与 IP/SYSID 匹配均不是认证。
- 校验后向本机各机独立 SDK UDP 端口转发完整帧；SDK 反向输出经 `Gateway.send` 单播到配置的设备 IP 和 `udp_port`。控制回包使用设备最近到达的接收 socket，以维持对称端口。
- 反向转发包含目标 SYSID 检查，未验证时仍允许 HEARTBEAT；target 0 仅为 PING/TIMESYNC 放行。Offboard 位置目标还有租约/streaming 门控。**这些是有发送能力的控制防护，不构成只读边界。**
- 状态快照提供原始接收量、心跳 age/gap、CRC、丢弃/待解析字节、身份错误等；`dropped` 混合了未知候选、CRC、拒绝路由等情况，不是无线丢包计数。来源端口切换会重置 ingress 解析统计，因此不能把 ingress 计数一律当会话累计量。

## 3. 记录与诊断：源码事实（S3）

- 使用 HTTP GET 轮询运行中的地面站，不调用 command API；默认 0.1 秒，允许 0.02–5 秒。构建无代理 opener，避免 localhost 被环境代理转发。
- 支持扁平单机状态和 `vehicles` 列表；按用户 id 选择，未匹配则回退第一架 enabled，再回退列表首架。`/api/status` 与 `/status` 遇 404 时互换一次。
- 每条 sample 有 monotonic 相对时间 `t` 和 UTC `wall`，保存位置、高度、状态、动作、链路摘要和日志；event 与 sample 共用 JSONL。每轮 flush，文件排他创建，重名则附加序号。
- 速度由位置差分推导，目标历史窗口约 0.4 秒，保留约 1.2 秒数据；实现选择队列中首个满足至少 0.4 秒的点，实际基线可能接近 1.2 秒，并非严格 0.4 秒。垂直速度正负取决于该 HTTP 快照的 z 约定，不可直接套用原始 MAVLink NED z。
- 检测状态变化、水平估计跳变、未点动水平运动、起飞横移、窗口掉高、5 秒高度线性回归慢降、定位无效及低于起飞基准；条件触发/恢复用 latch，跳变有 cooldown。
- 使用地面站 `moving/action` 推断动作边界，区分指令期、结束后的约 2 秒收敛期以及空闲；记录点动掉高、回弹、升降无变化。它观察既有控制结果，本身不发送这些动作。
- README 明确这是地面站快照，不是飞控完整内部状态。轮询采样间隔不等于飞控消息更新周期；HTTP 成功不等于遥测新鲜；没有触发告警也不能证明飞行正常。

## 4. 配置逻辑：源码事实（S4、S5、S6）

- 示例公共监听 `0.0.0.0:14550`，5 个条目，前两机 enabled；IP 为 `192.168.20.201` 至 `.205`、SYSID 1–5、设备/接收端口 14551–14555、内部 SDK UDP 端口 14601–14605、gRPC TCP 端口 50051–50055。
- 校验包含：飞机数量 1–5；id/sysid/ip/sdk_port/grpc_port 各自唯一；id 字符集与 1–32 长度；SYSID 为整数 1–244（245 留给地面站）；enabled 必须 bool；名称非空；各端口整数 1024–65535；监听与设备接收 UDP 不得冲突 SDK UDP。
- 设备地址须可解析 IPv4，并排除 multicast、unspecified、全局广播地址；并未全面排除 loopback、保留地址或子网定向广播。不同飞机允许相同 `udp_port`，监听时去重，这并不必然是错误，因为按 IP 路由。
- 启动先尝试绑定接收 UDP/SDK UDP/gRPC TCP 检查占用，再真正启动网关与 SDK；提前检测有价值，但关闭预检 socket 到实际绑定之间仍有竞争窗口。
- 所有配置条目（含 disabled）参加唯一性及字段校验。此工程若独立采用配置模型，应明确是否保持这一行为，而不是悄悄改变语义。

## 5. 值得借鉴与独立实现建议

以下都是新工程建议，不表示已落地。

### 5.1 值得借鉴

1. **接收、解析、统计、展示与控制隔离**：以 S2 的纯接收思路为主要参考，而不是从 S4 删除几个按钮后继续运行双向 SDK 网关。
2. **以已知 CRC 验证建立边界**，支持分片/粘连/损坏后重同步；对未知 dialect 明确显示“未解析”，不按猜测身份分配飞机。
3. **来源隔离和身份异常可见**：每个源独立解析，显示 IP/端口/SYSID/COMPID 与预期的差异；把路由匹配称为“来源匹配”，避免误称密码学认证。
4. **原始证据可重放**：记录原始 datagram、端点与单调时间，重放复用同一解析路径且不打开网络，实现可复现诊断。
5. **明确计数含义**：分别展示接收、消息、CRC、未知候选、丢弃字节、缓存和心跳 age/gap；不要合成虚假的“丢包率”。
6. **新鲜度与缺测显式表达**：过期或无效字段显示未知，不把最后一次有效数值永久显示成实时遥测。UTC 用于对齐，monotonic 用于间隔。
7. **可解释事件**：阈值、时间窗、触发证据与恢复均可追溯；原始样本与派生告警分层，避免后续算法变更丢失原始证据。

### 5.2 需要改进或避免照搬

- **资源与输入防护**：S2 全量 records、S3 累积 events 可持续增长；应流式统计、限制文件/记录/来源数/缓存/队列、支持轮转与背压，并对 malformed JSON/Base64、字段缺失、非有限值、时序倒退报告清晰错误。S1 的帧长有协议上限，但仍需限制外部输入块和处理预算。
- **记录元数据与可复现性**：建议首条 schema/version、应用版本、dialect、时间基准、监听配置、来源过滤及脱敏策略；原始证据不可覆盖。S2 summary 当前会写入同名文件，建议也采用明确覆盖策略。
- **坐标与估计值语义**：标注 NED/ENU、米、弧度/度、上正/下正与参考原点；速度差分应按实际时间间隔且拒绝过期样本/长断档，支持 estimator reset 后清空历史。估计跳变不是已证实的物理瞬移。
- **谨慎使用“未指令”告警**：纯遥测工具不掌握全部遥控/其他地面站/机载控制意图。没有 `moving/action` 不应默认“无人下令”；应报告“观察到运动，控制意图未知”。固定每样本 0.15 m 跳变阈值随采样周期变化，不能断言真实机体不可能达到。
- **断链与恢复**：HTTP 失败目前主要输出终端日志；应将失败/缺测/恢复也写入结构化日志，避免跨长断档直接计算速度和趋势。明确心跳过期、位置过期、整链路无包是不同状态。
- **目标选择失败必须可见**：S3 指定不存在的 vehicle id 会默默回退另一机，独立实现应报错或显示未匹配，不应录错飞机。
- **统计窗口清晰**：心跳最大间隔目前主要度量两个已到达心跳之间的间隔，末尾持续沉默应由 age 单独表达；不同源/会话不混合；来源切换时明确新会话和累计计数。
- **日志可靠性**：S3 使用列表前缀对比捕捉 GCS 日志，滚动窗口后可能重复记录；建议来源事件序号。flush 不等于 fsync，需按故障恢复需求选择持久化策略。
- **配置校验**：采用明确 schema 和可读错误，检查对象/数组类型与缺少字段，避免 bool 被当数字、NaN/Infinity 进入计算。端口冲突按协议与地址判断，不应简单要求所有 TCP/UDP 数字不同。
- **安全与隐私**：限制监听范围，展示来源白名单；IP/SYSID 可伪造，未知包不自动加入信任列表。原始日志包含网络地址与飞行数据，需权限、保留与脱敏策略。非 loopback HTTP 读取应明确权限与安全要求。
- **验证矩阵**：独立构造 MAVLink 1/2、分片、粘包、坏 CRC、噪声、未知 ID、签名长度、跨源隔离、时序异常、日志 round-trip、端口占用及资源边界测试；这些是建议测试，非本次已执行结果。

## 6. 不可引入的发送及控制行为

本新工程若定位为只读飞行诊断，边界必须是**不向飞控、数传或 MAVLink 链路发送任何数据**，而不只是“不解锁”。读取本地状态的 HTTP GET 请求可以存在，但应与 MAVLink 零发送承诺明确区分。

| 参考中的行为或潜在路径 | 独立只读实现要求 |
| --- | --- |
| S4 `Gateway.send` / UDP `sendto`、向 SDK bridge 转发 | 不引入双向桥接，不设反向发送通道；只收与离线解码足够 |
| 启动 `System`、MAVSDK server 或其他可能主动握手的客户端 | 不使用其自动心跳/请求/控制生命周期；依赖应最小化 |
| HEARTBEAT、PING/TIMESYNC 回复、自动请求遥测速率/消息/参数 | 即便看似查询或保活，也属于链路发送，应禁止；仅被动观察已有流 |
| POST 单机/组 commands、`submit(action)` | 不提供或转发解锁、上锁、起飞、降落、停止、点动、模式切换 API |
| Offboard start/stop、位置/速度/姿态设定点与租约续期 | 不包含后台设定点任务或控制状态机；门控/租约不是只读保证 |
| 参数写入、任务上传、校准、重启、RC override 等 | 不添加这些功能，也不因诊断告警自动操作飞控 |
| S4 退出时维持网关以让控制器请求降落（源码注释说明其意图） | 退出只关闭 socket、任务和文件，不发“安全清理”降落/停止/上锁 |
| S6 的安装启动/实机飞行步骤 | 仅作为上游说明，不在研究中执行，也不作为新工程默认行为 |

建议以结构性措施验证只读：网络层只暴露接收接口；离线重放不创建 socket；不导入控制模块；用本机隔离测试和发送 API 探针确认接收/错误/退出路径没有 MAVLink 发送。HTTP 服务返回诊断结果与文件写入不属于飞控控制，但不应借“只读”之名隐藏任意远程 HTTP 访问。

## 7. 最终结论与独立实现声明

参考的主要价值是 CRC 重同步、来源隔离、原始 datagram 重放、心跳/损坏统计，以及具有上下文的快照记录。S2 是严格被动接收的直接参考；S3 对飞控无控制发送，但依赖另一个正在运行且可能主动控制的地面站；S4/S6 描述的整体系统是主动控制地面站，**不能整体复用到只读诊断工程**。

本笔记没有复制落地任何上游实现，也不构成授权/许可证结论。后续代码应依据公开协议与明确的新工程需求独立设计，记录借鉴来源；如计划复制代码，须先单独核实许可证。本次没有取得未读文件或实机证据，所有改进建议均应通过独立测试后再声称实现有效。
